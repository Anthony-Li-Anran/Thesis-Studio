# Thesis Studio 工作流程

## 核心理念

**场景定位**：用户带着明确的研究题目入场，系统负责落地执行。AI 辅助研究，用户做关键决策。

整个项目按**状态机**推进，7 个状态对应 4 个工作流阶段。

---

## 状态机

`
 INIT → EXPLORING → DESIGNING → RESEARCHING → WRITING → POLISHING → COMPLETED
   │                                                  │
   └──────────────── 开题阶段 ────────────────────────┘
                        │
                        └────────── 研究阶段 ──────────┘
                                                 │
                                                 └────── 撰写阶段 ──────┘
                                                                       │
                                                                       └── 交付阶段 ──┘
`

| 状态 | 英文 | 含义 |
|------|------|------|
| INIT | Initial | 项目刚创建，等待用户开始 |
| EXPLORING | Exploring | 文献探索：围绕题目检索、筛选、综述 |
| DESIGNING | Designing | 研究规划：基于文献综述做研究问题、方法、数据方案的决策 |
| RESEARCHING | Researching | 研究实施：数据收集、清洗、分析、结果 |
| WRITING | Writing | 论文撰写：大纲到初稿 |
| POLISHING | Polishing | 打磨交付：润色、查重、格式、答辩 |
| COMPLETED | Completed | 全部完成 |

---

## 阶段一：开题

**覆盖状态：INIT → EXPLORING → DESIGNING**

### What the user brings

- 一个**明确的研究题目**（如"BERT微调在中文医疗文本分类中的应用研究"）
- 专业背景
- 可选：导师要求、时间节点

> 系统面向**场景B**：用户带着题目来，AI 辅助落地。不负责从零"帮用户找题目"。

### EXPLORING — 文献探索

| 任务 | 说明 |
|------|------|
| 检索式构建 | 根据题目自动生成中英文检索式 |
| 批量检索 | 对接学术数据库，批量拉取文献 |
| 去重筛选 | 按标题/摘要初筛，按全文质量深度筛选 |
| 文献库 | 输出结构化文献库（元数据、摘要、质量评分） |
| 文献综述 | 按主题聚类，梳理脉络，标注关键论点和争议点，识别研究空白 |

### DESIGNING — 研究规划（Planning）

DESIGNING 是整个研究的核心决策环节。基于 EXPLORING 的文献综述，AI 辅助用户做关键决策，**直接决定论文质量的下限**。

| 任务 | 说明 |
|------|------|
| 问题定义 | 基于文献综述和研究空白，提炼具体研究问题，提出可验证假设 |
| 方法设计 | 确定研究范式（定性/定量/混合），设计数据方案和分析策略 |
| 方案确认 | 整合研究问题 + 假设 + 方法 + 数据方案，用户确认后进入实施 |

> DESIGNING 的产出不是"开题报告文档"，而是**一组驱动后续阶段的结构化决策参数**（研究问题、假设、方法、数据方案）。这些决策错了，后面全错。

### 里程碑

研究方案确认（研究问题、假设、方法、数据方案已明确）。状态进入 RESEARCHING。

---

## 阶段二：研究

**覆盖状态：RESEARCHING**

### 前置条件

- 研究问题与假设已确认
- 研究方法方案已确认
- 数据来源已明确

### RESEARCHING — 研究实施

| 任务 | 说明 |
|------|------|
| 数据收集 | 对接 API、解析数据集、生成问卷、爬取数据等。记录元信息 |
| 数据清洗 | 处理缺失值、异常值，统一格式。输出清洗报告 |
| 数据分析 | 统计分析 / 文本分析，生成图表和统计表格。脚本可复现 |
| 结果解读 | 解释结果含义，逐一验证假设。标注显著发现和意外结果 |

### 里程碑

分析结果全部产出，假设验证明确。状态进入 WRITING。

---

## 阶段三：撰写

**覆盖状态：WRITING**

### 前置条件

- 开题报告和文献综述
- 分析结果
- 文献库

### WRITING — 论文撰写

| 任务 | 说明 |
|------|------|
| 大纲构建 | 生成详细大纲（章、节、段落要点），用户确认后开始 |
| Introduction | 研究背景、文献回顾、研究空白、研究问题 |
| Methods | 研究设计、数据来源、分析方法 |
| Results | 核心发现，图表辅助 |
| Discussion | 结果解读、与文献对话、局限性 |
| Conclusion | 总结、贡献、未来方向 |
| 引用管理 | 正文引用与参考文献自动对应（GB/T 7714 / APA） |
| 图表生成 | 分析结果转学术图表，嵌入对应位置 |

### 里程碑

论文初稿完成。状态进入 POLISHING。

---

## 阶段四：交付

**覆盖状态：POLISHING → COMPLETED**

### 前置条件

- 论文初稿已完成

### POLISHING — 打磨交付

| 任务 | 说明 |
|------|------|
| 全文润色 | 学术语言规范化，逻辑连贯性检查 |
| 查重检查 | 检测重复率，标注问题段落，给出修改建议 |
| 格式规范 | 字体、行距、页边距、标题层级、图表编号、参考文献 |
| 答辩 PPT | 提取核心内容，生成演示文稿 |
| 问答准备 | 预测评委问题，准备应答要点 |

### 里程碑

论文终稿完成，查重通过，答辩材料齐全。状态进入 COMPLETED。

---

## 质量检查点

| 状态 | 检查项 |
|------|--------|
| EXPLORING → DESIGNING | 文献覆盖度够不够 |
| DESIGNING → RESEARCHING | 研究问题可行、方法合理 |
| RESEARCHING → WRITING | 数据质量、方法正确、结果可复现 |
| WRITING → POLISHING | IMRaD 完整、逻辑连贯、引用准确 |
| POLISHING → COMPLETED | 查重通过、格式合规、材料完备 |

---

## 状态流转规则

- **线性推进**：按状态顺序，不可跳跃（INIT 除外，可直接进入 EXPLORING）
- **阶段内迭代**：每个状态内允许多轮修改
- **回溯**：后期发现问题可回退到任意前置状态（如 WRITING 时发现数据不够，回退到 RESEARCHING）
- **用户控制**：每个状态结束需用户确认，系统不自动推进
