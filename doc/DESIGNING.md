# DESIGNING 阶段设计文档

> 研究总规划（Planning）：基于文献综述做关键决策，产出完整的研究方案——涵盖论文架构、实验设计、调查方案、理论推导路径。

---

## 一、定位

DESIGNING 是整个研究的**核心决策环节**。它不仅是设计论文的章节结构，更是制定一份**完整的研究总规划**：

- **论文架构**：章节如何组织
- **实验/调查方案**：理工科做什么实验，人文社科做什么调查
- **理论推导路径**：需要推导哪些理论，从哪里出发
- **数据分析方案**：用什么方法分析什么数据

这些决策直接决定论文质量的下限。DESIGNING 的产出是一份 Markdown 文档，承载两个角色——**研究总规划**（告诉 RESEARCHING 怎么做）和**论文大纲**（告诉 WRITING 怎么写）。

---

## 二、输入

| 输入 | 来源 | 说明 |
|------|------|------|
| 用户原始方向 | 项目创建时填写 | 用户带入场的研究方向，经过 EXPLORING 后可能调整 |
| 格式要求 | 默认模板 + 用户自定义 | 内置预设模板，也支持用户上传 Word/LaTeX/PDF 或输入文字描述作为自定义格式要求 |
| 文献综述 | EXPLORING 产出 | 围绕用户方向进行的文献检索、筛选、聚类、综述结果 |
| 文献库 | EXPLORING 产出 | 已入库的论文元数据（标题、作者、摘要、关键词、质量评分） |
| 研究空白 | EXPLORING 产出 | 综述中标注的未被覆盖的研究方向 |

### 格式要求与大纲模板

格式要求和大纲模板通过页面内的**抽屉卡片**管理，提供默认模板，也允许用户上传自定义要求。

```
DESIGNING 页面 Header 中 [格式要求] 按钮
    ↓
弹出右侧抽屉卡片
    ├── 预设模板列表（理工科 IMRaD / 文科五章 / 社科六章 / 自定义）
    ├── 上传自定义模板（Word/LaTeX/PDF 或文字描述）
    └── 当前生效的约束条件预览
    ↓
AI 提取并整理为结构化 JSON（供代码机械执行）
    ↓
用户选择/确认 → 大纲结构受约束
```

> 格式要求抽屉可随时打开修改，修改后大纲结构自动适配。

## 三、输出：研究总规划

### 核心产出

一份 Markdown 文档，即是**研究总规划**也是**论文大纲**。看结构是论文大纲，看内容是研究决策。两者是同一份产出的两个视角。

### 默认模板（IMRaD 扩展版）

```
# 论文题目

## 1 绪论
### 1.1 研究背景
### 1.2 研究问题
### 1.3 研究意义

## 2 文献综述
### 2.1 理论基础
### 2.2 核心概念界定
### 2.3 相关研究述评
### 2.4 研究空白与本研究的理论框架

## 3 研究设计
### 3.1 研究范式
### 3.2 研究假设
### 3.3 实验/调查方案
### 3.4 数据来源与采集
### 3.5 分析方法

## 4 预期结果
### 4.1 预期数据产出
### 4.2 预期分析结果
### 4.3 理论贡献预期

## 5 讨论框架
### 5.1 结果解读方向
### 5.2 与文献对话方向
### 5.3 局限性预判

## 6 结论
### 6.1 研究总结
### 6.2 创新与贡献
### 6.3 未来方向
```

> 模板由格式要求驱动。不同学科/学校模板会产生不同的章节结构。

### 大纲粒度规则

大纲中每个小节标题必须**刚好描述"研究什么"**，不涉及"怎么做"：

| 粒度 | 示例 | 判定 |
|------|------|------|
| 太粗 | `3.1 研究方法`、`4.1 实验设计` | 未指明具体研究方向，驳回 |
| 刚好 | `3.1 Softmax Kernel with Random Fourier Features`、`4.1 Long Sequence Classification` | 指明了研究方向，不含实现细节，通过 |
| 太细 | `3.1 用PyTorch实现RFF`、`4.1 在ImageNet上训练` | 包含工具名、数据集名、操作步骤，驳回 |

> 此规则为硬性约束。确认大纲时系统会通过 LLM 自动校验粒度，不通过则阻止进入 RESEARCHING。

### 论文题目

DESIGNING 阶段确定最终的论文题目。用户原始方向经过 EXPLORING 文献探索后，在 DESIGNING 中结合文献综述和研究空白，最终敲定论文题目。

## 四、前端设计

### 设计原则

参考 ChatGPT Canvas、Claude Artifacts、Cursor、V0 等主流 AI 创作工具的布局模式：
- **双栏布局**：对话驱动，产物为核。聊天是辅助手段，产物是最终目标
- **产物侧占更大比例**（~65%），对话侧窄而紧凑（~35%）
- **产物侧支持编辑/预览/分屏三种模式切换**

### 界面布局

```
┌────────────────────┬──────────────────────────────────┐
│  Header: 返回 | 阶段进度 | [格式要求] | [文献库] | 主题 | 语言  │
├────────────────────┼──────────────────────────────────┤
│   聊天室 (~35%)     │   大纲编辑器 (~65%)               │
│                    │  ┌─ Checklist ────────────────┐  │
│  @Researcher       │  │ ☐ 题目  ☐ 绪论  ☐ 综述    │  │
│  @Debater          │  │ ☐ 研究设计  ☐ 预期结果    │  │
│  @Reviewer         │  │ ☐ 讨论  ☐ 结论            │  │
│                    │  └────────────────────────────┘  │
│  [Agent 讨论区]     │  # 论文题目                      │
│  [用户输入区]       │  ## 1 绪论                       │
│  [建议按钮]         │  ### 1.1 研究背景                 │
│                    │  ...                              │
│                    │                                   │
│  ───────────────── │  [编辑 | 预览 | 分屏] 切换         │
│  [确认大纲] [保存]  │                                   │
└────────────────────┴──────────────────────────────────┘
```

### 编辑器三模式

| 模式 | 说明 | 使用场景 |
|------|------|----------|
| **编辑模式** | 纯 Markdown 源码编辑，语法高亮 | 用户直接撰写和修改大纲内容 |
| **预览模式** | 渲染后的学术格式预览，只读 | 检查结构完整性、层级关系 |
| **分屏模式** | 左编辑右预览，同步滚动 | 精细调整时对照源码和效果 |

### Checklist 组件

大纲编辑器顶部常驻一个紧凑的 Checklist 条，实时反映各章节完成状态：

- 每个顶级章节一个勾选项（☐ 题目 / ☐ 绪论 / ☐ 综述 / ☐ 研究设计 / ☐ 预期结果 / ☐ 讨论 / ☐ 结论）
- 自动检测：章节下所有子节有内容时自动勾选，空章节保持未勾选
- 手动勾选：用户也可手动点击勾选，覆盖自动检测
- 视觉反馈：全部勾选时 Checklist 变为绿色，提示可进入下一阶段

### 格式要求抽屉

点击 Header 中的 [格式要求] 按钮，从右侧滑出抽屉卡片：

- **预设模板**：理工科 IMRaD / 文科五章 / 社科六章，一键选择
- **自定义上传**：上传 Word/LaTeX/PDF 文件或输入文字描述
- **约束预览**：展示当前生效的结构规则清单（章节数、必含章节、格式规范）
- 修改后大纲结构自动适配

### 文献库按钮

与 EXPLORING 一致的文献库按钮，点击弹出文献库对话框，供 Researcher 引用和用户查阅。

### 与 EXPLORING 的复用

- 复用 ChatRoom 组件（@mention、流式输出、建议按钮、Agent 头像/颜色）
- 复用双栏布局框架（`flex:1; display:flex; overflow:hidden`），仅替换右侧面板内容
- 复用 Header（返回按钮、阶段进度、主题切换、语言切换）
- 复用 LiteratureLibrary 对话框
- 新增：多 Agent 支持（ChatRoom 扩展为多 Agent 群聊）、Markdown 大纲编辑器、Checklist、格式要求抽屉

## 五、交互方式

### 多 Agent 协同讨论（混合模式）

DESIGNING 采用混合模式：默认自动辩论，用户可随时 @ 指定 Agent 发言或打断。

| Agent | 角色 | 职责 |
|-------|------|------|
| **Researcher** | 文献专家 | 基于 EXPLORING 的文献库和综述，为大纲提供文献支撑——"这个论点有哪些论文支撑""这个实验方案在哪些文献中被验证过""这个理论框架的源头是什么" |
| **Debater** | 质疑者 | 挑战假设和方法选择——"为什么选这个方法？""实验结果的可复现性如何保证？""理论推导的假设前提是否成立？""样本量是否足够？" |
| **Reviewer** | 学术审稿人 | 从学术标准审查总规划——检查逻辑完整性、方法论严谨性、实验/调查方案可行性、结构合理性、是否符合格式要求 |

发言规则：
- **默认自动辩论**：用户给出问题后，Agent 按逻辑顺序自动发言（Researcher → Debater → Reviewer → Researcher 回应...），形成迭代打磨
- **智能判断 + 硬限制**：LLM 判断当前谁最应该发言，避免无意义的轮次；最多 3 轮自动辩论后等待用户介入
- **用户可 @ 介入**：用户可随时 @ 指定 Agent 发言，或打断当前辩论
- **用户可直接发言**：不 @ 时，消息先发给所有 Agent，由 Agent 自行判断是否回应

### 大纲更新：建议模式（Diff 卡片）

AI 不直接修改右侧编辑器，而是在聊天中发出 **Diff 对比卡片**，支持单条或多条建议，用户逐条确认。

```
┌─────────────────────────────────────────┐
│  🔄 Researcher 建议修改总规划            │
│                                         │
│  ┌─ 建议 1 ──────────────────────────┐  │
│  │ 章节: 3.3.1 实验设计               │  │
│  │ - 旧: 待定                         │  │
│  │ + 新: 采用2×2被试间设计，自变量A   │  │
│  │       （两个水平）和B（两个水平），  │  │
│  │       因变量为...，每组30人。       │  │
│  │         [确认] [修改] [拒绝]       │  │
│  └────────────────────────────────────┘  │
│  ┌─ 建议 2 ──────────────────────────┐  │
│  │ 章节: 3.5.3 理论推导路径           │  │
│  │ - 旧: 待定                         │  │
│  │ + 新: 从Hotelling模型出发，引入... │  │
│  │         [确认] [修改] [拒绝]       │  │
│  └────────────────────────────────────┘  │
│                    [全部确认] [全部拒绝]  │
└─────────────────────────────────────────┘
```

> 大纲的最终控制权在用户手中。AI 可以建议，但只有用户确认后才会真正修改。

### 确认按钮

聊天区底部 Footer，与 EXPLORING 位置一致，放置 [确认大纲] 按钮。

### 阶段完成条件

DESIGNING 阶段完成需同时满足：

| 条件 | 说明 |
|------|------|
| **用户确认** | 用户点击"确认大纲"按钮，明确表示满意 |
| **Reviewer 通过** | Reviewer Agent 给出最终审查通过，包含粒度检查结论 |
| **Checklist 全绿** | 所有章节已填写、方法论已明确、格式要求已满足 |
| **粒度校验通过** | LLM 自动校验大纲粒度，所有小节标题必须刚好描述研究内容 |

满足全部条件后，阶段进度推进，状态进入 RESEARCHING。

### 核心交互流程

```
用户输入 @Researcher / @Debater / @Reviewer
    ↓
单Agent: 直接回复 + @Researcher时触发DiffCard
多Agent: 进入辩论循环 (R→D→R, 最多3轮)
    ↓
Reviewer通过 或 达到最大轮数
    ↓
Researcher汇总修改建议 → DiffCard弹出
    ↓
用户逐条确认/拒绝 → 应用到大纲编辑器
    ↓
用户点击保存 → 持久化到DB + 写入outline.md
用户点击确认 → 粒度校验 → 通过则推进到RESEARCHING
```

### 辩论结束条件

1. **用户主动停止** — 输入框发送消息时中断
2. **Reviewer通过** — 回复包含 PASS/approved/通过/批准 等关键词，且必须包含"粒度检查通过"
3. **达到最大轮数** — 默认3轮，结束后由Researcher汇总

### 持久化

- 聊天消息: 保存/确认时同步到 `project.exploring_state["messages"]`
- 大纲Markdown: 同时写入 `data/projects/{id}/outline.md` 供后续阶段使用
- 阶段导航: 返回按钮将状态回退到EXPLORING，可重新进入
